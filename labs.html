OVERVIEW / LABS & SOURCES

Check the platform.
Trace the real calls.

Short exercises for readers who already know x86 and virtualization. Hardware is useful, but source-level tracing works without an SGX or TDX machine.

01 / HARDWARE

Verify more than a CPU flag

Treat each command as one piece of evidence, not a complete readiness verdict.

LayerCheckInterpretation
SGX CPUgrep -m1 -o "sgx" /proc/cpuinfoA visible flag is a lead; confirm CPUID capabilities, firmware and EPC size.
SGX Linuxls -l /dev/sgx_enclaveThe enclave driver is present; permissions and a working sample still matter.
TDX hostdmesg | grep -i "virt/tdx"Kernel initialization messages help distinguish disabled firmware or a module failure; dmesg may need privilege.
TDX hostcat /sys/devices/faux/tdx_host/versionRead the module version if this sysfs path exists on the running kernel.
TDX guestls -l /dev/tdx-guestThe guest device supports TD report requests; it does not by itself prove a remote verifier accepts the TD.

Run only the commands relevant to your machine. No device node or CPU flag alone establishes end-to-end support.
